# 支付渠道配置与上线检查

支付配置入口：后台 → 支付渠道。渠道密钥只写不读，保存后以 AES-256-GCM 加密；启用和修改配置均要求管理员密码 + TOTP。

## 支付宝官方当面付

系统使用支付宝开放平台 `alipay.trade.precreate` 创建预下单，前端展示支付宝返回的二维码；支付结果只认服务端异步通知，不相信浏览器跳转结果。

开通前需要在支付宝开放平台完成：

1. 创建网页/移动应用并完成上线审核。
2. 为应用签约当面付产品，并配置 RSA2 应用公钥。
3. 在后台填写 AppID、支付宝账号 PID（`seller_id`）、应用私钥、支付宝公钥和公网 HTTPS 异步通知地址。
4. 支付方式选择“当面付扫码”，保存校验通过后再启用。

默认正式网关为 `https://openapi.alipay.com/gateway.do`。异步通知地址应为：

```text
https://你的域名/api/pay/notify/ALIPAY_OFFICIAL
```

回调入账依次校验 RSA2 签名、AppID、seller_id、交易状态、订单号、支付宝流水号和创建支付时锁定的人民币金额。渠道后来被停用，也会继续处理停用前已经创建订单的合法回调。

> 代码完整支持的是“普通公钥模式”的当面付与电脑网站支付。是否能在真实商户号使用，仍取决于支付宝对该应用和商户主体的审核、签约及经营类目权限；没有签约当面付时，接口会返回支付宝业务错误。

## 易支付协议

填写网关根地址、商户 PID、商户密钥、支付类型和异步通知地址。系统按常见 Epay 协议生成 MD5 签名，回调校验签名、PID、状态、订单号、渠道流水和金额。

```text
https://你的域名/api/pay/notify/EPAY
```

易支付是兼容协议，不同服务商可能扩展参数或应答文本；上线前必须使用所选服务商的测试订单验证一次创建、跳转、异步通知和重复通知。

## Stripe

填写 Secret Key、Webhook Signing Secret 和三位币种代码。Webhook 至少订阅 `checkout.session.completed`，地址为：

```text
https://你的域名/api/pay/notify/STRIPE
```

## USDC / USDT

后台不保存钱包私钥。公开的 EVM 收款地址可直接在“支付渠道”页面设置；服务器环境变量仍可作为首次部署兜底：

```text
KA_MERCHANT_ADDRESS=0x你的EVM收款地址
```

支持 USDC@Base、USDC@Polygon、USDT@BSC；链、代币合约、RPC 和确认数在 `application.yml` / `application-prod.yml` 管理。启用前后台会检查收款地址格式。

## 上线前通用检查

- `site.url` 使用公网 HTTPS 域名，Nginx 正确转发 `/api/pay/notify/**`。
- 不要给支付回调加登录、验证码或浏览器跳转依赖。
- 用 `0.01` 或渠道允许的最小金额完成一次真实测试，确认二维码/跳转、异步回调、自动发货和重复回调幂等。
- 检查服务器时间同步、数据库唯一约束和 `KA_AES_KEY` 持久化；更换 AES 主密钥会导致旧渠道配置无法解密。
- 配置 Telegram 管理告警，任何渠道启停或密钥更新都会即时通知并写入审计日志。
